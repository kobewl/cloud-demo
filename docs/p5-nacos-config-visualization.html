P5 Nacos 配置中心 · 数据流可视化

配置怎么从 Nacos 下发到服务，又怎么做到"改配置不重启，实时生效"？以 cloud-demo 真实接口出入参演示。

Spring Cloud Alibaba 2023.0.3.2 Nacos Server 3.2.1 spring.config.import @RefreshScope

01这次做了什么

把两个服务的 数据库连接、MyBatis-Plus、业务开关 等配置从本地 yml 挪到 Nacos 配置中心，并验证动态刷新。

改造前
application.yml（本地）：
├─ server.port       8081
├─ spring.datasource  ← 写死在包里
├─ mybatis-plus       ← 写死在包里
└─ shop.notice       ← 写死在包里
改配置 = 重新打包 + 逐个重启
改造后
application.yml（本地，只留启动必需）：
├─ server.port       8081
├─ application.name  service-product
└─ spring.config.import
     └─ optional:nacos:service-product.yaml?refreshEnabled=true

Nacos 配置中心（service-product.yaml）：
├─ spring.datasource  ← 外置，控制台可改
├─ mybatis-plus       ← 外置
└─ shop.notice        ← 外置，改完秒级生效

02一次配置下发的完整数据流

注意：箭头 3 和 4 是两条"链路"——启动时拉一次（HTTP），之后变更靠推送（gRPC 长连接监听）。

开发者Nacos 控制台
改配置 → 发布
→写入
Nacos Server 3.2.1配置存储 + 变更推送
⇄gRPC 长连接
监听变更
NacosClient 2.3.x服务内嵌，启动拉取
→注入
Spring EnvironmentPropertySource 合并
→@Value
@RefreshScope BeanController 重建
返回新值
Java 类比：`spring.config.import` ≈ 往 Spring `Environment` 的 `PropertySource` 链上再挂一个远程属性源； `@RefreshScope` ≈ 对单个 Bean 的定向 `refresh()`（重建 + 重新注入 `@Value`），不是整个容器重启。

04版本关键点（最容易踩的坑）

1. bootstrap 已废弃 2023.0.1.3+

SCA 2023.0.1.3 起不再兼容 bootstrap 方式。网上大多数教程还是 bootstrap.yml 方案，在你的版本直接不生效。必须用 spring.config.import 写在 application.yml 里。

2. Nacos 3.x OpenAPI 大改 Server 3.2.1

发布配置要用 POST /nacos/v3/admin/cs/config， 参数是 groupName（不是 group），鉴权带 Authorization: Bearer <token>。 v1/v2 的 cs/config 路径已 404。

3. 客户端兼容性 实测通过

SCA 2023.0.3.2 内置 nacos-client 2.3.x，服务端 3.2.1。 官方兼容性表确认 3.x 服务端兼容 2.x 客户端，本项目已实测 配置拉取 + 动态刷新均正常。
