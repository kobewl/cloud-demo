## 一、你要学什么

1. **API 网关**（Gateway）为什么是微服务架构的"门面"：统一入口、路由转发、集中治理
2. 网关的**路由**是怎么配置的：`Path` 断言 + `lb://` 负载均衡 URI
3. **网关路由配置外置 Nacos**：配置即代码，路由改动不用重启网关
4. **Sentinel 限流**为什么做在网关上：按 route 维度设 QPS，超限返回 429
5. **订单服务**的下单流程：Feign 查商品 → 扣库存 → 落订单，跨服务事务怎么做补偿

---

## 二、生活类比

- **API 网关** ≈ 商场的**总大门/前台**：所有顾客（请求）先进大门，由前台告诉你
  "买书去 3 楼（service-product）、买零食去 B1（service-stock）、退换货去服务台（service-order）"。
  没有大门之前，你得自己记住每个店铺的准确位置（每个服务的 IP 端口）。
- **网关限流** ≈ 商场**限流闸机**：高峰期每秒只放 2 个人进"退换货区"（order-route 2 QPS），
  超了就在门口拦下（返回 429），而不是让所有人都挤进去把服务区压垮。
- **订单服务补偿** ≈ 你先在**前台扣了预约号**（扣库存），结果发现**填表失败**（落订单失败），
  前台再把预约号**还给你**（回补库存）。两个系统之间没有"原子操作"，只能事后补救。

**Java 类比**：
- Gateway 路由 ≈ `DispatcherServlet` + `HandlerMapping`：请求进来按路径（`Path` 断言）
  找到对应的 Handler（目标服务），`lb://service-product` ≈ 用 Spring Cloud LoadBalancer
  从注册中心解析真实地址（类似 `@LoadBalanced RestTemplate`）。
- Sentinel 网关限流 ≈ Servlet `Filter` 里做**计数器限流**：放行前先查"这秒还能不能放"，
  超了直接短路返回，**业务代码根本不会执行**。
- 分布式事务补偿 ≈ 两个本地 `@Transactional` 之间没有全局事务，只能**手动逆操作**
  （扣多了就加回来）——这是 Seata TCC 模式的雏形。

```
                ┌──────────────────────────────────────┐
                │            gateway (8080)             │
                │  统一入口 + 路由 + Sentinel 限流        │
                │  路由配置外置 Nacos (gateway.yaml)      │
                └────────┬──────────┬──────────┬────────┘
                         │          │          │
                Path=/api │          │          │ Path=/api/order/**
                /product/**│   /api/stock/**   │
                         ▼          ▼          ▼
                 service-product  service-stock  service-order
                    (8081)           (8082)         (8083)
                    │                │              │
                    │  Feign 调用    │              │ Feign 查商品
```

这是网关带来的核心价值（服务位置解耦）。

## 四、实现步骤

### 1. 新建 gateway 模块

**pom.xml 关键依赖**（注意：网关是 WebFlux 应用，**不能引 `spring-boot-starter-web`**，会冲突）：

```xml
<!-- 核心：Spring Cloud Gateway（WebFlux） -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-gateway</artifactId>
</dependency>
<!-- Nacos 服务发现：lb:// 路由靠它解析实例地址 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-discovery</artifactId>
</dependency>
<!-- LoadBalancer：Spring Cloud 2023 移除 Ribbon 后必须显式引入 -->
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-loadbalancer</artifactId>
</dependency>
<!-- Sentinel 限流 + 网关适配 -->
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-sentinel</artifactId>
</dependency>
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-alibaba-sentinel-gateway</artifactId>
</dependency>
```

**启动类**：`@SpringBootApplication` + `@EnableDiscoveryClient`（网关本身也是 Nacos 的一个服务）。

### 2. 路由配置（外置到 Nacos `gateway.yaml`）

```yaml
spring:
  cloud:
    gateway:
      routes:
        # 商品服务：/api/product/** 转发到 service-product
        - id: product-route
          uri: lb://service-product
          predicates:
            - Path=/api/product/**
        # 库存服务
        - id: stock-route
          uri: lb://service-stock
          predicates:
            - Path=/api/stock/**
        # 订单服务
        - id: order-route
          uri: lb://service-order
          predicates:
            - Path=/api/order/**
        # 动态路由演示：/api/config-test/notice → 重写为 /api/config/notice
        - id: config-test-route
          uri: lb://service-product
          predicates:
            - Path=/api/config-test/**
          filters:
            - RewritePath=/api/config-test/(?<segment>.*), /api/config/$\{segment}
```

**要点**：
- `id` = 路由唯一标识，也是 Sentinel 限流的资源名（后面用 `"order-route"` 限流）
- `uri: lb://service-product` = 走 LoadBalancer，从 Nacos 解析 `service-product` 的实例
- `Path` 断言 = 匹配请求路径
- `RewritePath` = 路径重写（演示网关的过滤器能力）

### 3. Sentinel 网关限流配置类

```java
@Configuration
public class SentinelGatewayConfig {

    @PostConstruct  // 应用启动后自动注册规则
    public void init() {
        // 1. 定义限流规则：每条路由 = 一个资源，独立 QPS 上限
        Set<GatewayFlowRule> rules = new HashSet<>();
        rules.add(new GatewayFlowRule("order-route")       // 下单是贵重操作，限严
                .setResourceMode(SentinelGatewayConstants.RESOURCE_MODE_ROUTE_ID)
                .setCount(2)                                // QPS 上限 2
                .setIntervalSec(1));                        // 统计窗口 1 秒

        rules.add(new GatewayFlowRule("product-route")
                .setResourceMode(SentinelGatewayConstants.RESOURCE_MODE_ROUTE_ID)
                .setCount(5)
                .setIntervalSec(1));

        // 2. 加载规则
        GatewayRuleManager.loadRules(rules);

        // 3. 被限流时的降级返回（HTTP 429 + 友好 JSON）
        GatewayCallbackManager.setBlockHandler((exchange, t) ->
                ServerResponse.status(HttpStatus.TOO_MANY_REQUESTS)
                        .contentType(MediaType.APPLICATION_JSON)
                        .bodyValue("{\"code\":429,\"msg\":\"请求过于频繁，请稍后再试\"}"));
    }
}
```

**关键配置**（`application.yml`）：
```yaml
spring:
  cloud:
    sentinel:
      filter:
        enabled: false   # 必须关！否则与网关限流适配器冲突，控制台出现 URL 资源
```

### 4. 订单服务 service-order（8083）

**下单流程**（`OrderServiceImpl.create`）：

```java
@Override
public Long create(OrderCreateDTO dto) {
    // ① 查商品（Feign 调 service-product）
    R<ProductInfoDTO> productR = productFeignClient.getProduct(dto.getProductId());
    if (productR.getCode() != 0) {
        throw new BusinessException(productR.getCode(), productR.getMsg());  // 错误透传
    }
    if (productR.getData() == null) {
        throw new BusinessException(ResultCode.PRODUCT_NOT_FOUND);
    }

    // ② 扣库存（Feign 调 service-stock，原子扣减防超卖）
    R<Void> deductR = stockFeignClient.deductStock(dto.getProductId(), dto.getCount());
    if (deductR.getCode() != 0) {
        throw new BusinessException(deductR.getCode(), deductR.getMsg());    // 透传"库存不足"
    }

    // ③ 落订单：商品信息快照 + 总金额
    ProductInfoDTO product = productR.getData();
    Order order = new Order();
    order.setProductId(product.getId());
    order.setProductName(product.getName());          // 快照：商品改名不影响历史订单
    order.setPrice(product.getPrice());
    order.setCount(dto.getCount());
    order.setTotalAmount(product.getPrice().multiply(BigDecimal.valueOf(dto.getCount())));
    order.setStatus(0);

    // ④ 落单失败 → 补偿：把库存加回来
    if (!this.save(order)) {
        stockFeignClient.addStock(dto.getProductId(), dto.getCount());      // 手动补偿
        throw new BusinessException(ResultCode.ORDER_CREATE_FAIL);
    }

    return order.getId();
}
```

**为什么不能一把梭 `@Transactional`？** ① ② 是跨服务 HTTP 调用（另一个数据库），
本地事务管不到。只能"扣库存成功 → 落订单 → 失败回补"。这是 Seata TCC 的思想雏形。

### 5. 逻辑删除（order 表）

- 表加 `deleted TINYINT DEFAULT 0`
- 实体字段 `@TableLogic`
- Nacos 配置 `mybatis-plus.global-config.db-config.logic-delete-field: deleted`
- 效果：查询自动 `WHERE deleted=0`，删除自动变 `UPDATE ... SET deleted=1`

## 六、踩坑记录

1. **网关不能引 `spring-boot-starter-web`**：Gateway 是 WebFlux（响应式），
   引了 web 会启动冲突。所以网关不依赖 common-core（它内部带 web）。

2. **`spring-cloud-starter-gateway` 的版本不是 2023.0.3**：它的真实版本是 4.1.x，
   由 `spring-cloud-dependencies` BOM 管理，pom 里**不写版本号**（写了反而找不到）。

3. **Sentinel 网关限流必须 `filter.enabled: false`**：否则会启用 Servlet 过滤器适配，
   与网关限流冲突，且控制台出现 URL 资源。

4. **`spring.cloud.sentinel.filter.enabled=false` 要在 gateway 模块配**，不是业务服务。

5. **Feign 错误要透传，不要吞**：库存不足时，库存服务返回 `70201`，
   订单服务要 `throw new BusinessException(code, msg)` 原样传给前端，
   不能自己写死 `ORDER_CREATE_FAIL`。为此把 `BusinessException` 扩展成支持 `(code, msg)`。

6. **`BigDecimal` 不能 `*`**：`price * count` 编译不过，要用
   `price.multiply(BigDecimal.valueOf(count))`。

7. **逻辑删除字段加 `@TableLogic`**：只配全局 `logic-delete-field` 不够，
   实体字段上还要标 `@TableLogic`（双保险）。

8. **Nacos 3.x 的 OpenAPI 和 2.x 不同**：查订阅者用
   `/nacos/v3/admin/ns/client/service/subscriber/list`；服务列表用 `/nacos/v3/admin/ns/service/list`。
   控制台"订阅者列表"显示为空，可能是控制台版本调用的旧接口在 3.x 服务端不匹配，
   但**订阅关系实际存在**（API 可查到 service-product 有 2 个订阅者）。

9. **Nacos 配置中心 Data ID 要带后缀**（`.yaml`）。

## 七、思考题

1. 网关路由配置外置到 Nacos 后，改路由怎么生效？（提示：`refreshEnabled=true` 监听）
   如果网关是唯一入口，它挂了会怎样？
2. Sentinel 的限流规则如果也想动态更新（不重启网关），怎么做？
   （提示：`spring-cloud-alibaba-sentinel-datasource` + Nacos 数据源）
3. 订单服务"先扣库存再落单"的补偿方案有什么缺陷？
   （提示：补偿调用本身可能失败；进程在扣库存后、落单前崩溃怎么办？）
   Seata 是怎么解决这个问题的？
4. 为什么订单表要存 `product_name` 快照而不是下单时去查商品服务？
   如果订单只存 productId，商品改名后历史订单会怎样？
5. 网关限流 2 QPS 是基于"每 1 秒窗口"，如果某个瞬间来了 5 个请求但分散在 3 秒内，
   会全部通过吗？（提示：Sentinel 滑动窗口算法）
