## 一、你要学什么

1. **为什么需要"集中式"日志**：四个服务散在四台"机器"（进程）里，各自写日志文件，出问题要一台台翻
2. EFK 三个角色各干什么：**采集（Filebeat）→ 存储（Elasticsearch）→ 查询（Kibana）**
3. **倒排索引**：ES 为什么能"秒搜"——和书的索引页一个道理
4. Spring Boot 侧只需一行配置：日志额外落文件
5. 版本对齐铁律 + Filebeat 多行合并（异常堆栈不"碎"）

## 二、生活类比

- **没有集中式日志** ≈ 小区每户自己记家庭账本，物业想查"昨晚谁家跳闸"得挨家敲门翻本子
- **Filebeat** ≈ **邮差**：守在每户门口（日志文件），有新信（新日志行）就收走送去档案馆；只管搬运不拆信
- **Elasticsearch** ≈ **档案馆**：把信按关键词编好目录（倒排索引），找"上个月所有含'跳闸'的信"一秒出结果
- **Kibana** ≈ **档案馆的检索台**：不存东西，只提供搜索页面和展示
- **倒排索引** ≈ **书后面的索引页**："分布式事务"这个词出现在第 12、45、78 页——从"词"找"页"，而不是从"页"找"词"

**Java 类比**：
- Filebeat ≈ 日志界的 **Feign**：业务代码不感知它，它在旁边默默干活（零侵入）
- `logging.file.name` ≈ 给 SLF4J 的输出多接一根水管：控制台一根（IDEA 里看），文件一根（Filebeat 收）

## 二点五、选型：为什么是 EFK，不是 ELK / Loki

| 方案 | 组成 | 特点 |
|------|------|------|
| **ELK**（传统） | Logstash 采集 | Logstash 是 JVM，重；擅长"边采边过滤转换"，简单搬运杀鸡用牛刀 |
| **EFK**（本项目） | **Filebeat** 采集 | Go 写的轻量采集器，只搬运不过滤，资源占用小；需要过滤时后面可以再挂 Logstash |
| **Loki**（轻量新贵） | Grafana 家的日志库 | 不建全文倒排索引、只索引标签，更省资源；查询能力弱于 ES。**计划后续对比学习** |

> liang 的计划：ES 和 Loki 都学，先学 ES（资料多、面试高频、还能当搜索引擎用）。

| 支柱 | 回答的问题 | 工具 | 本项目阶段 |

## 四、整体架构（数据流向）

```
四个服务（Mac 10.110.0.99）                Windows 10.110.0.170
┌─────────────────────┐
│ gateway.log          │
│ service-product.log  │    ①盯文件增量读取      ②推给 ES 存储
│ service-stock.log    │ ──────────────────→ Elasticsearch :9200
│ service-order.log    │   Filebeat（Docker 跑在 Mac）        ③Kibana 查询
└─────────────────────┘                                    Kibana :5601 ← 浏览器
        /tmp/logs/
```

关键点：**日志先落本机文件，Filebeat 再搬运**。为什么不直接推 ES？
1. 服务代码保持零侵入（只改配置，不写推送代码）；
2. ES 挂了日志也不丢——文件还在，Filebeat 会记住读到哪（registry），恢复后接着采。

## 五、接入步骤

### 1. 服务侧：日志落文件（每个服务的 application.yml，一行）

```yaml
logging:
  file:
    name: /tmp/logs/service-order.log   # 各服务写各的文件名
```

Spring Boot 默认只打控制台；加了这行 = 控制台 + 文件**双写**。和 tracing/metrics 一样属于"启动必需的基础设施观测配置"，放本地不外置 Nacos。

### 2. 部署 ES + Kibana（Windows Docker，版本铁律 7.17.28）

单节点学习环境的标准跑法（复现参考，以实际容器为准）：

```powershell
docker run -d --name elasticsearch -p 9200:9200 -p 9300:9300 `
  -e "discovery.type=single-node" -e "xpack.security.enabled=false" `
  docker.elastic.co/elasticsearch/elasticsearch:7.17.28

docker run -d --name kibana -p 5601:5601 `
  -e "ELASTICSEARCH_HOSTS=http://10.110.0.170:9200" `
  docker.elastic.co/kibana/kibana:7.17.28
```

- `xpack.security.enabled=false`：学习环境关掉账号密码，Filebeat 直连不用认证
- 防火墙放行 9200 / 5601（同 P10 的 netsh 命令套路）

### 3. Filebeat 配置（源文件 `docs/filebeat/filebeat.yml`，四段结构）

```yaml
filebeat.inputs:            # ① 输入：四个服务四条，各贴 service 标签
  - type: log
    paths: ["/tmp/logs/gateway.log"]
    fields: { service: gateway }
    fields_under_root: true # 标签提升为顶层字段，Kibana 里好按它过滤

multiline.pattern: '^[0-9]{4}-[0-9]{2}-[0-9]{2}'  # ② 多行合并：
multiline.negate: true      #    日期开头 = 新日志；at 开头的堆栈行拼到上一条
multiline.match: after      #    否则 Java 异常会被"碎"成几十条独立日志

output.elasticsearch:
  hosts: ["10.110.0.170:9200"]        # ③ 输出：推给 ES
  index: "filebeat-7.17.28-%{+yyyy.MM.dd}"  # 按天滚动索引

setup.template.enabled: false  # ④ 不自动装索引模板，让 ES 自动推断字段（学习简化）
```

### 4. 跑 Filebeat（Docker 方式，踩坑后的结论）

```bash
docker run -d --name filebeat \
  -v /tmp/logs:/tmp/logs:ro \
  -v ~/Documents/JavaProject/cloud-demo/docs/filebeat/filebeat.yml:/usr/share/filebeat/filebeat.yml:ro \
  docker.elastic.co/beats/filebeat:7.17.28
```

## 七、踩坑记录

1. **版本对齐是铁律**：原计划装 ES 8.15.3，实际环境是 **7.17.28**——Filebeat、Kibana 必须**严格同版本**，跨大小版本协议不兼容（8.x 默认开安全认证，配置方式也不同）。
2. **Filebeat 7.17 macOS 官方包只有 x86_64**：Apple Silicon（M 系列芯片）原生跑不了，要靠 Rosetta 转译；加上 Elastic 官网下载慢，最终放弃本地安装，**改用 Docker 跑 Filebeat 镜像**（挂载 /tmp/logs），反而更干净。
3. **多行合并必须配**：Java 异常堆栈的 `at com.xxx...` 行不以日期开头，不配 multiline 会被当成独立日志，一条异常碎成几十条，Kibana 里没法看。

## 八、思考题

1. 为什么 ELK 里的 Logstash 被 Filebeat 替代了？什么场景下仍然需要 Logstash？（提示：采集 vs 过滤转换）
2. 日志索引按天滚动（`filebeat-7.17.28-2026.08.21`）有什么好处？磁盘满了想删 30 天前的日志，删"索引"和删"文档"哪个快？（提示：倒排索引是整块建的）
3. 怎么让日志和 P9 的链路追踪"串"起来？（提示：日志格式里加 `%traceId`，Kibana 搜 traceId → 拿着同一个 ID 去 Zipkin 看瀑布图——这就是三件套联动）
4. ES 挂了 10 分钟，这期间的日志会丢吗？（提示：文件还在 + Filebeat 记住了读到哪）
5. Loki 和 ES 的核心取舍是什么？（提示：Loki 只索引标签不建全文索引——省资源 vs 搜得慢）

### ✅ 实战 A（2026-08-24 完成）：索引模式 + 按 service 过滤

1. ✅ Kibana `http://10.110.0.170:5601/app/discover` → 自动跳转 **Create index pattern**
   - Name 填 `filebeat-*`（`*` 通配符匹配所有 filebeat 索引，含按天滚动的 08.21/08.24）
   - Timestamp field 选 `@timestamp`
   - 点 Create index pattern → 显示 31 个字段（@timestamp/`_id`/`service` 等）
2. ✅ Discover 顶部 KQL 搜索框输入 `service: "service-order"` → 回车，**命中 266 hits**，每条日志带 `service: service-order` 标签
   - 原理：`service` 字段是 Filebeat 配置里 `fields: { service: xxx }` + `fields_under_root: true` 贴上去并提升为顶层字段
