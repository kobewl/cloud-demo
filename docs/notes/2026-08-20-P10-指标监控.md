# P10 · 指标监控（Prometheus + Grafana）

> 日期：2026-08-20
> 状态：✅ 完成，端到端验证通过（指标端点 → Prometheus targets 4/4 up → Grafana 大盘出图）
> 版本环境：Spring Boot 3.3.4 / Micrometer 1.13.4 / Prometheus + Grafana（Docker，Windows 10.110.0.170）

---

## 一、你要学什么

1. 指标监控是什么：和日志、追踪并列的**可观测性三件套**最后一根支柱
2. **拉取（pull） vs 推送（push）**：Prometheus 主动抓、Zipkin 被动收，方向相反
3. 三个指标类型：counter（只增）/ gauge（可增可减）/ histogram（分布）
4. Spring Boot 接 Prometheus 最少几步：加依赖 + 暴露端点
5. Grafana 只是"画图工具"：数据在 Prometheus，它用 PromQL 查完渲染

---

## 二、生活类比

- **Prometheus** ≈ **物业巡逻员**：每隔几分钟主动去各家门口看一眼水表电表（抓指标），抄回来记在账本上
- **Grafana** ≈ **物业大厅的大屏幕**：把账本上的数字画成趋势图，业主一眼看到今天用水用电高不高
- **指标（metric）** ≈ **水表读数**：CPU 用了几成、内存剩多少、请求每秒几个——都是"数字"
- **counter（计数器）** ≈ **电表**：只增不减，看"总共用了多少度"
- **gauge（仪表）** ≈ **水压表**：可升可降，看"当前压力多少"
- **histogram（直方图）** ≈ **快递耗时统计**：统计"多少快递 1 分钟内到、多少 5 分钟内到"——看分布

**Java 类比**：
- Micrometer ≈ 指标界的 **SLF4J**：统一接口，底层实现可换（Prometheus / InfluxDB / Datadog）
- `/actuator/prometheus` 端点 ≈ 一个**自动生成的报表页**：actuator 把 Micrometer 收集的指标按 Prometheus 格式打印出来

## 三、可观测性三支柱（回顾）

| 支柱 | 回答的问题 | 工具 | 数据怎么来 |
|------|-----------|------|-----------|
| **日志 Logging** | 发生了什么事 | `log.info` / ELK | 服务主动写 |
| **追踪 Tracing** | 一个请求走了哪条路、每步多久 | Zipkin（P9） | 服务**主动上报**（push） |
| **指标 Metrics** | 系统健康不健康、多快 | **Prometheus + Grafana**（P10） | Prometheus **主动来抓**（pull） |

P9 把 Zipkin 那条线走通了，P10 把指标这条线也补上——三件套齐了。

---

## 四、拉取 vs 推送（最重要的区别）

| 维度 | Prometheus（拉取） | Zipkin（推送） |
|------|-------------------|---------------|
| 谁主动 | **Prometheus 定时去抓** | 服务**主动上报** |
| 被监控方知道被谁监控吗 | 不知道，不用知道 | 知道（要配上报地址） |
| 配置里写谁的地址 | **服务的地址**（被监控方在哪） | Zipkin 自己的地址（上报到哪） |
| 类比 | 物业巡逻员上门抄表 | 各家主动去物业交表 |

> ⚠️ **这就是部署时最容易写反的地方**：P10 踩的坑就是 liang 把 Prometheus 的 target 写成了 Prometheus 自己的 IP（10.110.0.170），应该是**服务所在的 Mac（10.110.0.99）**。

## 五、接入步骤（代码侧，最少两步）

### 1. 加依赖（每个服务）

```xml
<!-- P10 指标监控：Micrometer 的 Prometheus 实现，把指标暴露成 Prometheus 拉取格式 -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

> 版本由 Spring Boot 3.3.4 BOM 管理为 1.13.4，不用手写。actuator 在 P9 已经加过了，不用重复加。

### 2. 暴露端点（每个服务的 application.yml）

```yaml
management:
  endpoints:
    web:
      exposure:
        include: prometheus,health,info   # ★ 关键：默认只暴露 health，必须显式加 prometheus
```

不加这行，`/actuator/prometheus` 返回 404，Prometheus 抓不到任何数据。

## 六、部署侧（Windows 服务器）

### Prometheus（需要配置 + 挂载）

`prometheus.yml`（项目源文件 `docs/prometheus/prometheus.yml`）：

```yaml
global:
  scrape_interval: 5s        # 每 5 秒抓一次

scrape_configs:
  - job_name: 'cloud-demo'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets:
          - '10.110.0.99:8080'   # gateway
          - '10.110.0.99:8081'   # service-product
          - '10.110.0.99:8082'   # service-stock
          - '10.110.0.99:8083'   # service-order
```

```powershell
docker run -d --name prometheus -p 9090:9090 -v C:\prometheus\prometheus.yml:/etc/prometheus/prometheus.yml prom/prometheus
```

### Grafana（纯可视化，一行命令）

```powershell
docker run -d --name grafana -p 3000:3000 grafana/grafana
```

### 防火墙放行

```powershell
netsh advfirewall firewall add rule name="Prometheus 9090" dir=in action=allow protocol=TCP localport=9090
netsh advfirewall firewall add rule name="Grafana 3000" dir=in action=allow protocol=TCP localport=3000
```

## 七、验证记录（真实数据）

### ① 指标端点：`curl localhost:8081/actuator/prometheus`

返回 67 个标准 Prometheus 指标（`# HELP` 说明 + `# TYPE` 类型 + 数值）。

### ② 发请求后，HTTP 指标记录（QPS/耗时的数据源）

```
http_server_requests_seconds_count{method="GET",status="200",uri="/api/product/list"} 3
http_server_requests_seconds_sum{method="GET",status="200",uri="/api/product/list"} 0.09380525
http_server_requests_seconds_count{method="GET",status="200",uri="/api/product/{id}/detail"} 1
http_server_requests_seconds_sum{method="GET",status="200",uri="/api/product/{id}/detail"} 0.242617625
```

`count` = 请求次数，`sum` = 总耗时，一除就是平均耗时。`rate(count[1m])` 就是 QPS。

```

```

## 八、踩坑记录

1. **actuator 默认只暴露 health**：不加 `exposure.include: prometheus`，`/actuator/prometheus` 返回 404。新手必踩。

2. **targets 的 IP 写反（本次核心坑）**：liang 把 `prometheus.yml` 的 targets 写成 `10.110.0.170`（Windows 自己），结果 Prometheus 去抓 Windows 自己的 8080 端口——那上面是别的服务，返回 500：
   ```
   Error scraping target: server returned HTTP status 500
   ```
   **根因**：Prometheus 是**拉取模型**，targets 要写"**服务在哪台机器**"（Mac 10.110.0.99），不是"Prometheus 在哪"（Windows 170）。和 Zipkin 上报方向正好相反。
   **解法**：targets 改成 `10.110.0.99:8080~8083` 四个，`docker restart prometheus` → 4/4 up 全绿。

3. **target 数量写错**：liang 只写了 1 个 target 而不是 4 个，且误加了 zipkin target。应该是 4 个服务各一个。
