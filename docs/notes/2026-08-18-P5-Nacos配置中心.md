# P5 · Nacos 配置中心（配置文件外置 + 动态刷新）

> 日期：2026-08-18
> 状态：✅ 完成，端到端验证通过
> 版本环境：Spring Cloud Alibaba 2023.0.3.2 / Nacos Server 3.2.1（Docker）

---

## 一、你要学什么

1. 为什么微服务需要**配置中心**（而不是继续用本地 `application.yml`）
2. 本项目版本下（SCA 2023.0.3.2）接入 Nacos Config 的**唯一正确姿势**：`spring.config.import`
3. 什么是**动态刷新**：改配置不重启，线上实时生效（`@RefreshScope`）

---

## 二、生活类比

- 配置中心 ≈ **中央厨房统一发菜谱**：每个服务员（服务实例）不用自己记菜谱
  （本地配置文件），从中央（Nacos）取，总厨改一个配方，所有分店自动跟着变。
- 动态刷新 ≈ 改菜谱后**不用重新招服务员**：`@RefreshScope` 只把"拿着菜谱的人"
  重新培训（重建 Bean），而不是整个店重开（重启 JVM）。

**Java 类比**：
- `spring.config.import` ≈ 往 Spring `Environment` 的 `PropertySource` 链上
  **再挂一个远程属性源**，启动时从 Nacos 拉取并合并。
- `@RefreshScope` ≈ 对**单个 Bean** 的定向 `refresh()`（重建 + 重新注入 `@Value`），
  而不是 `ApplicationContext.refresh()` 那种全局重来。

---

## 三、为什么配置要外置？

| 场景 | 本地配置的痛点 | 配置中心解决 |
|------|--------------|-------------|
| 数据库连接改了 | 改 yml → 重新打包 → 逐个重启 | 控制台改一处，全部实例自动生效 |
| 环境切换（dev/test/prod） | 每个环境一套包 | 同一份代码，配置按环境（namespace）隔离 |
| 开关/阈值类配置 | 每次都要发布 | 随时改，`@RefreshScope` 秒级生效 |

## 四、关键版本事实（重要，别踩坑）

> ⚠️ Spring Cloud Alibaba 从 **2023.0.1.3 起**：
> - **bootstrap.yml 方式已废弃**（网上 90% 教程还是这套，在你的版本无效）
> - `shared-configs` / `extension-configs` / 按 `application.name` 自动加载配置 全部废弃
> - **统一用 `spring.config.import`**（Spring Boot 2.4+ 的配置导入标准）

你的 Nacos Server 是 **3.2.1**（Docker 镜像 `nacos/nacos-server:latest`），
客户端是 SCA 2023.0.3.2 内置的 nacos-client 2.3.x。官方升级手册确认：
**Nacos 3.x 服务端兼容 2.x 客户端**（本机实测通过，见下方验证记录）。

## 五、实现步骤

### 1. 加依赖（services/pom.xml，两个服务继承）

```xml
<dependency>
    <groupId>com.alibaba.cloud</groupId>
    <artifactId>spring-cloud-starter-alibaba-nacos-config</artifactId>
</dependency>
```

### 2. 本地 application.yml 只留"启动必需项" + 配置中心入口

```yaml
server:
  port: 8081          # 端口留在本地（基础设置，拉不到配置也得能起）

spring:
  application:
    name: service-product
  cloud:
    nacos:
      discovery:      # 注册中心地址
        server-addr: 127.0.0.1:8848
        username: nacos
        password: nacos
      config:         # 配置中心地址（同一个 Nacos）
        server-addr: 127.0.0.1:8848
        username: nacos
        password: nacos
  config:
    import:
      - optional:nacos:service-product.yaml?refreshEnabled=true
```

- `optional:` 前缀 = Nacos 里没这份配置也能启动（不快速失败）；去掉则拉不到直接启动失败
- `?refreshEnabled=true` = 开启监听，配置变更自动推送（配合 `@RefreshScope`）
- **datasource / mybatis-plus / 自定义项全部挪走了**（见 `docs/nacos-config/`）

### 3. 在 Nacos 创建配置（Data ID 带后缀）

`docs/nacos-config/service-product.yaml` 内容示例（配置即代码）：

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: "jdbc:mysql://127.0.0.1:3306/product_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai"
    username: root
    password: "123456"

shop:
  notice: "【动态配置】商品服务公告：全场图书 8 折，满 99 包邮"
```

### 4. 动态刷新演示接口

```java
@RestController
@RequestMapping("/api/config")
@RefreshScope                              // 关键：配置变更时重建此 Bean
public class ConfigController {

    @Value("${shop.notice:暂无公告}")        // 值来自 Nacos 配置中心
    private String notice;

    @GetMapping("/notice")
    public R<String> notice() {
        return R.ok(notice);
    }
}
```

## 六、验证记录（真实入参/出参）

### ① 配置成功从 Nacos 拉取（启动日志）

```
[Nacos Config] Load config[dataId=service-product.yaml, group=DEFAULT_GROUP] success
[Nacos Config] Listening config: dataId=service-product.yaml, group=DEFAULT_GROUP
```

### ② 接口正常（datasource 来自 Nacos 配置）

```
GET http://localhost:8081/api/config/notice
→ {"code":0,"msg":"成功","data":"【动态配置】商品服务公告：全场图书 8 折，满 99 包邮"}

GET http://localhost:8081/api/product/list
→ {"code":0,"msg":"成功","data":[{"id":2084199084315619330,"name":"《微服务从入门到实战》",...}]}
```

### ③ 动态刷新（核心验证）

```
第 1 次调用 notice  → "全场图书 8 折，满 99 包邮"
在 Nacos 控制台把 shop.notice 改为 "全场图书 8 折（动态刷新验证成功，未重启服务！）" 并发布
第 2 次调用 notice（约 10 秒后）→ "全场图书 8 折（动态刷新验证成功，未重启服务！）"  ✅ 无重启生效
再改回原值并发布 → 第 3 次调用恢复初始值   ✅ 反向刷新也验证
```

### ④ 原有 Feign 链路不受影响

```
GET http://localhost:8081/api/product/2084199084315619330/detail
→ {"code":0,"data":{"product":{...},"stock":{"quantity":0}}}
```

## 七、踩坑记录

1. **bootstrap.yml 不生效**：SCA 2023.0.1.3+ 已放弃 bootstrap 模式，
   配置必须写在 `application.yml` 并走 `spring.config.import`。
   判定方法：启动日志出现 `[Nacos Config] Load config... success` 即为成功。

2. **Nacos Server 是 3.2.1，OpenAPI 大改**：
   - `POST /nacos/v1/cs/configs`（v1）→ **404 已移除**
   - `POST /nacos/v2/cs/config`（v2）→ **404 已移除**
   - 3.x 用 `POST /nacos/v3/admin/cs/config`，参数是 `groupName`（不是 `group`），
     鉴权要带 `Authorization: Bearer <token>`（`accessToken` 参数也不行，v3 管理接口 403）
   - 顺带：`/nacos/v1/console/health/readiness` 健康检查路径也不存在（无 mapping），
     判断 Nacos 是否就绪改用 `/nacos/v1/auth/login` 是否 200。

3. **login 接口还是 v1**：`POST /nacos/v1/auth/login`（v3 没动这个），返回 `accessToken`。

4. **Data ID 一定要带后缀**（如 `.yaml`），Spring 按后缀识别格式。

5. **Shell 环境杀后台进程**：在 IDE 的 shell 里 `nohup mvn ... &` 启动的服务，
   命令返回后进程会被回收。验证要"启动+等待+curl"放同一条命令里完成。

## 八、思考题

1. 为什么 `server.port` 不放进 Nacos？如果放进去，Nacos 挂了会怎样？
2. `@RefreshScope` 为什么只能重建"挂上注解的 Bean"？如果改的是连接池参数
   （如 datasource），只重建一个 Controller 够吗？（提示：连接池 Bean 也要标）
3. `optional:nacos:` 里的 `optional` 去掉会有什么行为差异？什么时候该用哪种？
4. 配置中心里存 `password`（如 123456）有什么风险？生产上怎么处理？
